Це модель [[Cloud Computing]], де ти орендуєш базову інфраструктуру: [[Virtual Machine|VM]], диски, мережу — і сам ставиш ОС, middleware і застосунки.

Як приклад: оренда порожньої квартири — стіни, електрика, вода є, але меблі, ремонт і порядок — на тобі. Оренда складу — простір і охорона є, а що і як там зберігати — твоя справа. Таксі з водієм — це вже не IaaS; IaaS ближче до оренди авто без водія.

У всіх цих прикладах принцип однаковий: **тобі дають «сирі» ресурси; як їх зібрати в робочу систему — твоя відповідальність**.

==IaaS== (Infrastructure as a Service) — найнижчий рівень cloud-послуг. [[Cloud Provider]] дає:
1. Compute — зазвичай [[Virtual Machine|VM]] (іноді bare metal)
2. Storage — диски, томи, object storage
3. Networking — virtual networks, IP, firewall, load balancer

Ти керуєш:
1. ОС і її оновленнями
2. Runtime / БД / вебсервером (якщо ставиш сам)
3. Кодом застосунку й даними
4. Безпекою на рівні гостьової ОС і доступів

#### Що на тобі vs на провайдері
| Шар | Хто керує |
|---|---|
| Фізичні сервери, DC | Provider |
| [[Virtualization|Hypervisor]] / host virtualization | Provider |
| VM, диски, VPC | Provider дає, ти конфігуруєш |
| ОС всередині VM | Ти |
| Застосунок і дані | Ти |

#### Типові приклади
1. AWS EC2, Azure Virtual Machines, Google Compute Engine
2. Virtual disks / block storage
3. VPC / VNet — твоя ізольована мережа в cloud

#### Коли обирають IaaS
1. Потрібен повний контроль над ОС і стеком
2. Міграція існуючих серверів «як є» (lift-and-shift)
3. Нестандартне ПЗ, яке не сідає на [[PaaS]]

*IaaS = оренда інфраструктури. Вище за зручністю — [[PaaS]], ще вище (готовий продукт) — [[SaaS]].*
