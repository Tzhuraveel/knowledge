Це модель надання обчислювальних ресурсів (сервери, сховище, мережа, ПЗ) через Інтернет — замість купівлі й утримання власного обладнання.

Як приклад: електромережа дає струм «по запиту» — ти не будуєш електростанцію вдома. Таксі дає транспорт «по запиту» — ти не купуєш авто заради однієї поїздки. Streaming дає фільми «по запиту» — ти не купуєш DVD-колекцію.

У всіх цих прикладах принцип однаковий: **ресурси надаються як послуга через мережу, і ти платиш за використання, а не за володіння інфраструктурою**.

==Cloud Computing== (Cloud Computing) працює за тим самим принципом. Це спосіб отримувати через Інтернет:
1. Compute — потужність серверів для запуску програм
2. Storage — місце для даних
3. Networking — з'єднання між сервісами й користувачами
4. Software — готові застосунки або платформи для їх створення

*Cloud — не магія в небі: це чужі [[Host (network)|сервери]] у [[Data Center|Data Centers]], до яких ти доходиш через [[Network|мережу]].*

#### Моделі послуг (хто що керує)
1. [[IaaS]] — орендуєш «сиру» інфраструктуру (VM, диски, мережу)
2. [[PaaS]] — орендуєш платформу для деплою коду
3. [[SaaS]] — користуєшся готовим застосунком

#### Хто це дає
[[Cloud Provider]] — компанія, яка володіє [[Data Center|Data Centers]] і продає ці ресурси як сервіс (AWS, Azure, GCP тощо).

#### На чому це стоїть
Без [[Virtualization]] cloud у сучасному вигляді майже неможливий: один фізичний сервер ділиться на багато ізольованих [[Virtual Machine|VM]].

#### Benefits (навіщо взагалі cloud)
Порівняно з власним on-prem [[Data Center]]:

1. **Pay as you go** — fixed cost → variable cost. Немає великого upfront на будівлю/залізо/штат; платиш за те, що реально з'їв у місяці. Можна стартувати з малого.
2. **Economies of scale** — [[Cloud Provider]] купує залізо оптом по всьому світу → дешевше за одиницю ресурсу, ніж якби ти будував DC сам. Частина економії йде клієнту.
3. **Stop guessing capacity** — on-prem купуєш «на 3 роки вперед»: переоцінив — залізо простоює, недооцінив — scramble і деградація для юзерів. У cloud provisionиш під зараз і scale up/down за хвилини.
4. **Speed & agility** — test/experiment середовища піднімаєш швидко; не зайшло — видалив і витрати зупинились. Менше часу на provisioning, більше на продукт.
5. **Stop running [[Data Center|Data Centers]]** — racking, stacking, power, cooling, охорона — на провайдері. Ти фокусуєшся на клієнтах і коді, не на «тримати серверну».
6. **Go global in minutes** — замість місяців/років на свій DC в іншій країні деплоїш у Region провайдера ближче до юзерів.

*Підсумок: дешевше на старті й у масштабі, швидше експериментувати, легше рости географічно — без володіння фабрикою серверів.*

*Cloud Computing = доступ до чужої інфраструктури й ПЗ через Інтернет, зазвичай з оплатою за споживання.*
